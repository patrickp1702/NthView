What Behaviour-Driven Development is, how Cucumber turns plain-language Gherkin scenarios into automated tests, and how to keep a Cucumber suite readable, fast and trustworthy.

Glossary

BDD ch. 2
Behaviour-Driven Development: agreeing on behaviour in concrete examples before writing code, then automating those examples.
Flaky test ch. 5
A test that passes and fails without any change to the code, usually from timing, shared state or external dependencies.
Gherkin ch. 2
The plain-language format of feature files: Feature, Scenario, Given, When, Then.
Hook ch. 2
Code that runs before or after each scenario or step, for set-up and clean-up.
Living documentation ch. 2
Feature files that stay true because the suite runs them; the spec and the tests are the same text.
Scenario Outline ch. 3
One scenario template run once per row of an Examples table.
Step definition ch. 2
The code that runs for one Given, When or Then line; the glue between the scenario and the system.
Three amigos ch. 2
A product, development and test person working out examples together before anything is built.
