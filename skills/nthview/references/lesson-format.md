# Lesson format

A lesson is a folder under the repo-root `lessons/` directory (or, when NthView
is used as a plugin from another project, any folder the user chooses). It holds a
manifest and one view output per chapter. Nothing in a lesson is hand-written
HTML: every page is produced by `scripts/build-lesson.js`.

## Folder layout

```
lessons/
└── <lesson-slug>/
    ├── lesson.json                 # the manifest (below)
    ├── index.html                  # GENERATED contents page
    └── chapters/
        ├── 00-highlights.json      # the preview deck (nthview-highlights), always first
        ├── 00-highlights.html      # GENERATED
        ├── 01-<chapter-slug>.json  # the chapter's view data (source of truth)
        ├── 01-<chapter-slug>.html  # GENERATED by the chapter's view + lesson bar
        ├── 02-<chapter-slug>.json
        └── 02-<chapter-slug>.html
```

- `<lesson-slug>` and `<chapter-slug>` are kebab-case.
- Chapter files start with two digits so the order is visible on disk;
  `00-highlights` is always first.
- One chapter is exactly one view. Two angles on an idea are two chapters.

## lesson.json (schemaVersion 2)

| Field | Type | Required | Constraints | Description |
| :- | :- | :- | :- | :- |
| `schemaVersion` | integer | yes | `2` | Format version |
| `title` | string | yes | 1–80 | Lesson title |
| `description` | string | yes | 1–400 | One or two sentences on the contents page and in the library |
| `audience` | string | yes | 1–200 | Who it is for |
| `level` | string | yes | `beginner`, `intermediate`, `advanced` | Shown in the library and used as a filter |
| `domain` | string | yes | one of `security`, `software`, `science`, `business`, `philosophy`, `health`, `maths`, `language`, `history`, `arts`, `other` | Controlled top-level topic. Extend the list here first, then in `scripts/build-lesson.js` |
| `tags` | string[] | yes | 1–8, lowercase kebab-case, 2–30 chars, unique | Free vocabulary. The library filters by tag; reuse tags other lessons already use |
| `objectives` | string[] | yes | 2–7 items, 10–160 chars | What the learner will be able to do. Start each with a verb: explain, compare, apply, diagnose, decide |
| `prerequisites` | string[] | no | ≤6 items, ≤160 chars | What to know first; "None" is a fine single entry |
| `estimatedMinutes` | integer | no | 5–600 | Total time. If omitted, the sum of chapter `minutes` when every chapter has one |
| `glossary` | object[] | no | ≤20 of `{term 1–60, definition 1–300, chapter?}` | Terms unique beyond case; `chapter` is the file of first use. 5–15 terms is the sweet spot |
| `references` | object[] | no | ≤12 of `{title 1–120, url? https, note? ≤160}` | Further reading, shown on the contents page |
| `license` | string | no | ≤40 | SPDX id or similar |
| `language` | string | no | BCP-47, default `en` | Page language |
| `created` | string | yes | `YYYY-MM-DD` | When the lesson was first written. The library filters by it |
| `updated` | string | no | `YYYY-MM-DD`, not before `created` | Bump on every content change; the library sorts by it |
| `chapters` | array | yes | 2–30 Chapter objects, the first a `nthview-highlights` overview | In reading order |
| `next` | string | no | slug of an existing lesson | Where the last chapter's "Next lesson" link goes |

Chapter: `file` (string, `NN-kebab-case`, must match `chapters/<file>.json`),
`title` (1–80), `view` (an installed view skill name), `summary` (1–300),
and optionally `role` (one of `preview`, `structure`, `demonstrate`, `apply`,
`confront`, `consolidate`, `assess`, `recap`), `minutes` (1–120),
`objectives` (indexes into the lesson objectives this chapter serves) and
`terms` (glossary terms first introduced here).

Rules the builder enforces: the first chapter is `nthview-highlights`; a
`preview` role is first and a `recap` role is last, at most one each;
glossary `chapter` values and chapter `terms` must exist; `updated` is not
before `created`. It warns when no glossary, when an objective has no
chapter, when no chapter has the role `apply` or `assess`, and when the
duration cannot be computed.

```json
{
  "schemaVersion": 2,
  "title": "Compliance for Everyone",
  "description": "What compliance really means, told three ways.",
  "audience": "Anyone starting a job where rules matter.",
  "level": "beginner",
  "domain": "business",
  "tags": ["compliance", "workplace", "ethics"],
  "objectives": ["Explain what compliance is and who writes the rules", "Choose the compliant action in a realistic situation and say why"],
  "prerequisites": ["None"],
  "glossary": [{ "term": "Audit", "definition": "A planned check that the rules are being followed, by someone not doing the work.", "chapter": "02-a-week-at-brightpath" }],
  "created": "2026-10-22",
  "updated": "2026-10-30",
  "chapters": [
    { "file": "00-highlights", "title": "Highlights", "view": "nthview-highlights", "summary": "What this lesson covers, one card at a time.", "role": "preview", "minutes": 5 },
    { "file": "01-the-marigold-kitchen-case", "title": "The Marigold Kitchen Case", "view": "nthview-detective", "summary": "Crack the case and learn what compliance is.", "role": "demonstrate", "minutes": 15, "objectives": [0] },
    { "file": "02-a-week-at-brightpath", "title": "A Week at BrightPath", "view": "nthview-scenario-quiz", "summary": "Ten real decisions, each explained.", "role": "apply", "minutes": 15, "objectives": [1] }
  ]
}
```

## The Highlights chapter

Every lesson opens with `00-highlights`, a `nthview-highlights` deck that
previews the whole lesson without teaching it: a hook cover, one card per
chapter (kicker = chapter name, `href` = `0N-<slug>.html`), one number or
quote at most, a recap card, and a cta card whose `href` opens chapter 1.
Its `tags` are the lesson tags and its `kicker` names the chapter count and
duration. Follow `skills/nthview-highlights/SKILL.md` for the cards.

## Roles: what each view is for in a lesson

| Role | Meaning | Views that serve it |
| :- | :- | :- |
| `preview` | Hook, objectives, what is coming (always chapter 00) | Highlights |
| `structure` | The map of parts and relations, an advance organiser | Concept Map, Zoom Map |
| `demonstrate` | A worked example or a model to predict and tinker with | Sequence, Explorable Lab, Detective Case |
| `apply` | Use the ideas with explanatory feedback | Scenario Quiz, Courier, Explorable Lab |
| `confront` | Meet and rule out the tempting wrong model | Detective Case |
| `consolidate` | Interleaved practice over everything so far | Island Quest, Temple Run |
| `assess` | A scored check (Island Quest exam, Temple Run `strictMode`) | Island Quest, Temple Run |
| `recap` | Summary and transfer, never new content (last chapter) | Highlights |

Templates by content type, after `00-highlights`:

- **System or mechanism**: Concept Map → Explorable Lab → Scenario Quiz → Detective Case → Island Quest (→ Highlights recap).
- **Procedure or protocol**: Sequence → Concept Map or Zoom Map → Scenario Quiz → Detective Case → Temple Run.
- **Rule or judgement domain**: Detective Case → Concept Map → Scenario Quiz → Scenario Quiz or Courier (a second setting) → Island Quest.
- **Codebase or large system**: Zoom Map → Sequence → Courier or Detective → Scenario Quiz → Temple Run or Island Quest.

Six to eight chapters is the usual length. One formative check by the
fourth chapter, one summative check in the consolidation chapter.

## Build

```bash
node ${CLAUDE_SKILL_DIR}/../../scripts/build-lesson.js lessons/<lesson-slug>
```

The tool validates `lesson.json`, validates every chapter's JSON with its
view's validator, assembles each chapter page exactly as `build-html.js`
does, appends the lesson bar, writes `index.html`, and regenerates the
gallery registry so the lesson appears in the gallery's "docs and lessons"
dialog. `--all` rebuilds every lesson. `bun` and `deno run -A` run it
unchanged. With no JavaScript runtime, reproduce what the script writes by
hand: validate every chapter against its view's `references/schema.md`, build
each chapter page as `build-html.js` specifies, append the lesson bar exactly
as `lessonBar()` emits it, and write the contents page in the same shape as
an existing lesson's `index.html`.

## The lesson bar

Every chapter page gets a small fixed button in the bottom-right corner
showing `3/7`. Hovering, focusing or tapping it opens the bar: lesson title,
chapter title, Previous, Contents and Next chapter (or Next lesson / Finish on
the last chapter). It is injected after the view's bootstrap script and never
touches the view's code, so the chapter is still a valid standalone view
output.
